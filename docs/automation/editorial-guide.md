## 소식: 실제 최근 사건

- 발생일과 원문 게시일을 구분하여 확인합니다. 사건과 뉴스 원문 모두 발행 시점 최근 72시간 이내여야 합니다. 날짜만 확인되면 `YYYY-MM-DD`만 쓰고 시각을 만들지 않습니다.
- 적어도 서로 다른 기관·매체 2곳을 직접 읽고, 공식 발표 등 1차 자료를 1개 이상 포함합니다. 경제·사회·과학·국제·문화 등 상식으로 유익한 분야를 고릅니다.
- 핵심 요약 → 어떤 일이 있었나 → 왜 중요한가 → 배경과 맥락 → 생활의 영향 → 추가로 알아둘 점을 담습니다. 사실과 해석을 구분하고 정치적 사안은 균형 있게 씁니다.
- 4~5분: 제목·요약·기능 요약·본문을 합친 공백 제외 약 1,600~2,500자. 화면 읽기 시간은 500자/분으로 계산합니다. 분량은 반복 문장으로 채우지 않습니다.
- `event`에 주체(subject), 핵심 행동(action), 실제 날짜(occurredOn 또는 시각까지 확인한 occurredAt), 사건 키(key), 검증한 사실(facts 2개 이상), 키워드를 기록합니다.
- 동일 사건의 후속 보도는 parent의 사건 키를 `followUpOf`로 연결하고, 이전 모든 보도에 없던 중요 사실을 `newFacts`에 2개 이상 넣습니다. 새로운 사건 키·topicKey·id와 최신 출처를 사용합니다. 핵심 사실을 다시 표현한 것은 새 사실이 아닙니다.
- 믿을 수 있는 새 사건을 찾지 못하면 해당 그룹을 `holds`에 넣습니다. 오래된 뉴스나 출처를 만들지 않습니다. 다른 두 그룹의 발행은 계속합니다.

## 교양: 설명과 생활의 연결

철학·경제·건강은 3~4분, 공백 제외 약 1,100~2,000자. 개념·배경을 정확하게 설명하고 일상 사례와 스스로 생각할 질문으로 연결합니다. 다른 언어로 작성하거나 명언만 모으지 않습니다.

- 철학: 철학자와 핵심 개념을 구분합니다. 출처가 불명확한 명언·인용은 사용하지 않습니다. Stanford Encyclopedia, IEP, 원전 등 신뢰할 수 있는 자료를 읽습니다.
- 경제: 실제 사례로 개념을 설명합니다. 최신 수치를 쓴다면 `statistics: [{value, asOf: "YYYY-MM-DD", sourceUrl}]`도 기록합니다. 확정 수익·무조건 매수 같은 표현을 쓰지 않습니다.
- 건강: WHO, CDC, NIH, NHS, 질병관리청, Cochrane 등 정책에 허용한 의료·학술 자료에 근거합니다. 필요하면 출처 허용 목록은 사람이 검토해 확장합니다. 과장된 효능·개인별 진단·치료 지시는 쓰지 않습니다.

단어가 달라도 같은 핵심 개념이면 기존 주제입니다. `coreConcept`은 구체적이고 일관된 식별자로 쓰고, `topicKey`는 카테고리·주체·개념을 구분한 안정적인 키를 사용합니다. `semanticSummary`는 중복 판정에 필요한 핵심 명제를 짧게 씁니다.

## 후보 파일 형식

```json
{
  "schemaVersion": 2,
  "policyVersion": "2026-11-14.1",
  "date": "YYYY-MM-DD",
  "id": "고유한-실행-식별자",
  "drafts": [],
  "holds": []
}
```

아티클 공통 필드:

- `schemaVersion: 2`, `id`, `date`, `kind: daily`, `status: draft`
- `title`, `summary`, `highlights` (문자열 3개)
- `category`: `ai|tools|news|philosophy|economy|health`
- `group`: `development|life`, `publicationGroup`: `development|news|culture`
- `provider: cloud-agent`, `generatedAt`: 실제 생성 시각 (시간대 명시)
- 삶 글에는 `content: [{heading, paragraphs: [문자열], bullets?: [문자열]}]`를 3개 절 이상 작성합니다.
- 삶 글에는 `topicKey`, `coreConcept`, `keywords` (구체적 키워드 3개 이상), `semanticSummary`가 필요합니다.
- `sources: [{title, url, publisher, type: primary|reference, verifiedAt, publishedAt?}]`: 직접 읽은 공개 HTTPS URL만 기록합니다. `verifiedAt`은 실제 확인 시각입니다. 소식의 `publishedAt`은 필수입니다. 연·월·일만 확인했으면 날짜만 씁니다. 시각을 추측하지 않습니다.
- 소식에는 위의 `event`가 필수입니다.

보류 예: `holds: [{group: "news", code: "unverified-event", reason: "최근 72시간 사건을 독립 출처에서 확인하지 못했습니다."}]`.

후보가 전혀 없어도 보류 사유를 기록합니다. 기존 후보 파일이 있으면 최신 SHA를 읽고, 성공 그룹을 지우지 않은 채 실패 그룹의 후보만 교체합니다. 전체 파일을 쓰기 전에 현재 posts.json을 다시 읽어 동시 발행 여부를 확인합니다. 충돌하면 최신 파일을 다시 읽어 병합하며, 무작정 덮어쓰지 않습니다.

## 검증·발행·재시도

- 새 후보는 `GitHub create_file`, 기존 후보는 현재 SHA로 `update_file`합니다. 비밀키를 파일·프롬프트에 넣지 않습니다.
- 검증기는 요일별 발행 대상, 날짜·그룹·교양 발행 슬롯 순환·중복·분량·출처 접근과 뉴스의 72시간을 확인합니다. `publishedAt`은 해당 날짜 오전 6시로 설정하며, 화면은 그 이전에는 숨깁니다. 6시 이후 완료되면 완료 시점부터 보입니다. 정각 완료를 보장하는 장치는 아닙니다.
- 뉴스가 검증을 통과하지 못하면 `held`; 교양·개발의 검증 오류는 `failed`로 남깁니다. 성공 그룹은 되돌리지 않습니다.
- 결과는 posts.json과 publication-state.json을 읽어 확인합니다. 이력의 `code`, `message`, `attempts`로 원인을 찾습니다. 후보 저장만 성공한 상태를 ‘세 편 발행 완료’라고 보고하지 않습니다.
- 실패한 그룹만 수정한 뒤 같은 날짜 후보를 다시 저장하면 재검증합니다. 원본이 손상된 경우 덮어쓰지 않습니다.
- URL의 접근 가능성과 기록된 날짜를 자동으로 검사하는 것이지, HTTP 200만으로 모든 내용의 진실이 증명되는 것은 아닙니다. 자료의 실제 내용·발생일 확인과 의미 중복 검토는 생성자에게도 필수입니다.
