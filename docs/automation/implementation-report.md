# 전면 개편 구현 보고

기준: 2026-11-13. 배포·실행의 최종 성공 여부는 해당 커밋의 CI와 배포 결과를 함께 확인합니다.

## 1. 기존 구조와 자동화 분석

프런트엔드는 `docs/index.html` 한 파일의 HTML·CSS·JavaScript였습니다. 브라우저가 공개 GitHub `docs/data/posts.json` 배열을 직접 읽었고 목록·검색·두 카테고리 필터만 제공했습니다. 상세·페이지 URL 상태는 없었습니다. 개발 글의 공통 형식은 title, summary, highlights, why, repository/url 및 기술 메타데이터입니다.

초기의 GitHub 예약에는 누락 사례가 있었습니다. 이후 연결된 Sites 클라우드 작업이 GitHub 파일을 직접 갱신했고 11~13일에는 실제 게시 커밋이 확인됩니다. 기존 `hasDailyPost`는 같은 날짜에 어떤 글이든 있으면 완료로 간주해, 하루 세 그룹 확장에 그대로 쓸 수 없었습니다. Node.js 내장 테스트와 Qwen 기반 수동 복구 코드가 있었습니다. 호스팅은 기존 Sites 프로젝트의 정적 배포입니다.

## 2. 변경 파일과 구현

HTML 정적 구조를 유지하며 CSS, 앱 진입, 카테고리·조회·렌더링 모듈을 나눴습니다. 외부 JavaScript 라이브러리를 추가하지 않았습니다. `catalog.mjs`는 구형 스키마를 표시용으로 정규화하며 기존 객체를 재작성하지 않습니다. 새 글은 v2 필드를 추가하되 기존 배열·기본 필드를 보존합니다.

`publication.mjs`, `publication-cli.mjs`, `publish-git.mjs`, `publish-content.yml`로 후보 생성과 검증·발행을 분리했습니다. 기존 개발 검색과 요약 정책은 유지했고 그룹 단위 완료 검사와 공통 저장 경로에 연결했습니다. 각 경로의 역할은 README 표에 정리했습니다.

## 3. 브랜드와 정보 구조

표시 명칭은 진인사대천명이고 한자는 의미를 설명하는 문구에만 사용합니다. 헤드라인은 ‘하루를 기록하고, 생각을 나누는 공간.’입니다. 탭·메타 설명·Open Graph·Twitter Card·푸터·favicon·공유 이미지·구조화 데이터에 반영했습니다. 기존 공개 URL은 유지합니다.

상위 메뉴는 아티클 / 사진첩 / 게시판 세 개입니다. 아티클은 개발(AI·개발도구), 삶(소식·철학·경제·건강)을 필터로 탐색합니다. 검색·분류·페이지·상세는 쿼리 URL로 표현합니다. 날짜·계산된 읽기 시간·분류 배지·출처를 표시합니다. 사진첩은 4개 샘플 행사와 상세 그리드, 게시판은 지정된 환영 공지의 목록·상세를 제공합니다. 실제 사진·작성 폼·업로드·로그인은 추가하지 않았습니다.

## 4. 하루 세 그룹 발행

클라우드 예약 하나를 계속 생성자로 사용합니다. 오전 6시 Asia/Seoul이며, 성공한 그룹은 생성하지 않고 빠진 그룹만 후보 파일로 저장합니다. GitHub Actions만 게시글과 이력을 함께 커밋합니다. 기존 GitHub 자동 생성 예약은 제거하고 개발 수동 복구만 남겨 중복 예약을 피했습니다.

키는 ‘한국 날짜 + development/news/culture’입니다. 교양은 2026-11-13 철학부터 달력별 철학→경제→건강 순환입니다. 같은 날짜를 재실행해도 순환은 바뀌지 않습니다. 출처 확인 불가 뉴스는 보류하되 다른 그룹은 발행합니다. 손상된 원본은 덮어쓰지 않고 실패 기록을 남깁니다. Git push 충돌 시 최신 main을 가져와 발행을 다시 계산합니다.

## 5. 최신성·중복 검사

뉴스 사건 발생일과 각 원문 게시일을 독립 필드로 받으며, 날짜가 없거나 미래·72시간 초과이면 보류합니다. 직접 확인 시각도 필요합니다. 서로 다른 출처 2곳 이상과 1차 자료를 요구합니다. 날짜만 확인되면 시각을 만들어 넣지 않습니다.

전체 과거 글의 제목·저장소·topicKey·coreConcept·키워드·semanticSummary를 비교합니다. 핵심 개념 별칭도 정규화합니다. 뉴스는 주체·행동·발생일·사건 키를 비교하고 후속 보도에는 부모 사건과 새로운 중요 사실 2개 이상을 요구합니다. 같은 철학자의 다른 개념은 허용합니다. 자동 검사는 구조화 키와 텍스트 유사도에 기반하며 의미 중복을 완벽하게 판정하는 임베딩 시스템은 아닙니다. 생성자가 전체 이력을 의미적으로 비교하는 정책을 함께 사용합니다.

건강 출처는 의료·학술기관 허용 목록을 검토하며, 경제 수치 메타데이터에는 기준 날짜와 일치 출처를 요구합니다. URL 접근·형식·날짜 검사는 사실 전체의 진실을 증명하지 않습니다. 본문의 주장과 자료가 일치하는지 확인하는 편집 단계는 유지됩니다.

## 6. 호환성

개편 전 기존 글 7개를 삭제하거나 수정하지 않았습니다. AI/개발 도구 두 표기를 모두 읽고 안정적인 구형 ID로 상세 주소를 만듭니다. 공개 posts.json은 배열 그대로입니다. 기존 #board·#about 진입, 공식 저장소 링크, 검색 기능을 유지합니다. 새 메타 필드는 구형 소비자가 무시해도 기본 소개 글을 읽을 수 있습니다.

## 7. 검증

Node 내장 테스트는 날짜 경계, 순환, 하루 세 그룹, 부분 실패·재시도, 구형 데이터 보존, 동일 사건과 후속 보도, 주제 중복, 오래된·미래·누락 날짜, 분량, 의료 출처, 잘못된 JSON, 원본 무결성, 두 파일 저장 중 실패 복원, URL 상태, 카테고리·검색·페이지, 렌더링 이스케이프, 샘플 화면과 조회 어댑터를 확인합니다. 빌드는 필수 정적 파일, 기존 Sites ID, sitemap·robots를 검사합니다.

실제 검증에서 첫 실행은 뉴스의 참고 URL 한 곳이 GitHub 환경에서 403을 반환해 소식만 held로 기록했고, 철학은 발행하고 기존 개발 글은 보존했습니다. 접근 가능한 ESA·MPIA 자료를 다시 대조해 뉴스 후보만 수정한 두 번째 실행은 개발·교양을 건너뛰고 뉴스만 발행했습니다. 2026-11-13 실제 데이터는 세 그룹 각 1개이며 기존 7개 객체가 그대로 보존됩니다. Node 테스트 24개와 정적 빌드가 통과했습니다. 실행 기록: https://github.com/LeeHyungJoo/lab_playground-seed/actions/runs/43379397715 (부분 보류), https://github.com/LeeHyungJoo/lab_playground-seed/actions/runs/43379933200 (뉴스 재시도 성공). 테스트용 허구 뉴스를 실제 글로 게시하지 않았습니다.

현재 실행 환경에 Sites 브라우저 QA 런타임(cua_repl.js)이 없어 브라우저 상호작용·모바일 실제 기기 조작 검증은 제한됩니다. 반응형 CSS, 안전한 렌더링·라우트·직접 URL·정적 자산 응답을 별도로 점검합니다. 배포 서비스의 데스크톱 미리보기에서 새 브랜딩을 확인했고, fetch 수신자 바인딩과 좁은 검색 버튼·오른쪽 안내 영역의 줄바꿈을 보완했습니다. 실제 기기에서의 모바일 조작 검증은 여전히 별도 확인이 필요합니다.

## 8. NAS·DB 전환 경계

조회 인터페이스 `listArticles/listAlbums/listBoardPosts/getPublicationState/getCurrentUser`와 현재 JSON 구현을 분리했습니다. 작은 어댑터만 API 기반으로 교체할 수 있습니다. DB에는 날짜+발행 그룹 및 ID의 UNIQUE 제약, 트랜잭션·사건 키/주제 인덱스, 사용자·권한 모델이 필요합니다. NAS에는 업로드 검증·이미지 리사이징·접근 제어·백업 정책이 필요합니다. 지금은 DB나 NAS를 구축하지 않았습니다.

## 9. 미구현·주의 사항

사진 업로드·로그인·게시글 작성/수정/삭제·댓글·첨부파일·가족 권한은 의도적으로 미구현입니다. 사진과 행사 날짜는 샘플이며 실제 가족사진이 아닙니다. 현재 사이트는 기존처럼 공개입니다.

오전 6시는 목표 공개 시각입니다. 후보가 일찍 처리되면 publishedAt 전까지 화면에서 숨기고, 늦게 끝나면 완료 이후 표시합니다. 두 서비스 사이의 처리·스케줄 지연으로 정각 완료를 보장할 수 없습니다. 뉴스가 보류되면 하루 총 수는 3개 미만일 수 있으며, 이유를 기록합니다. 첫 확장된 클라우드 예약 실행 전에는 3개 후보의 무인 생성까지 검증됐다고 해석하면 안 됩니다. 외부 예약 프롬프트는 같은 자동화 ID를 갱신하며 적용 내용은 editorial-guide.md와 정책 파일로 관리합니다.
